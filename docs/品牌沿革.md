## 刻意保留的旧名残留

以下位置在改名完成后仍会出现旧名或旧标识，属于预期，审计时不应判为漏改：

1. `backend/src/main/java/com/yuzhua/security/JwtUtils.java`：两条历史泄漏密钥黑名单，用于启动期拒绝历史示例值。
2. `backend/src/test/java/com/yuzhua/security/JwtUtilsSecretTest.java`：对上述黑名单的断言，测试历史黑名单所必需。
3. `docs/部署步骤.md`：同两条历史 JWT 密钥示例，已注明「历史拒绝值，保留原样」；以及存量 Compose 升级时沿用的旧卷名 `pet-clinic_mysql_data` / `pet-clinic_uploads_data`（`README.md` 的存量 Compose 升级说明引用同两条旧卷名）。Docker 不支持重命名卷，保留旧卷名是保留数据的必要手段。
4. `sql/migrations/20261118_rename_database_to_yuzhua.sql`：迁移脚本必须引用旧库名 `pet_clinic` 才能完成库重命名，属于一次性迁移逻辑，保留原样。
5. `docs/品牌沿革.md`：本文件，记录旧名到新名的映射。
6. git 历史与已合并的旧 PR（含已清理的 `docs/test-evidence/**` 历史日志与图片、已删除的 `docs/愈爪改名计划-20261118.md`）。
